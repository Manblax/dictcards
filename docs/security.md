# Проверка секретов

Файлы `.env` и `.env.*` во всех каталогах, стандартные имена файлов ключей
и резервные копии исключены через `.gitignore`. Файлы `*.example` содержат
только примеры. Не используйте значения из примеров и тестов в production.
Не передавайте секреты через `NEXT_PUBLIC_*` или Docker build arguments.

Для проверки перед каждым локальным коммитом установите Gitleaks 8.30.1
из официального проекта `gitleaks/gitleaks` (на macOS: `brew install gitleaks`)
и включите hook в своём клоне:

```bash
git config core.hooksPath .githooks
```

Hook проверяет staged diff и блокирует коммит при обнаружении секрета
или отсутствии сканера. Также поддерживается локальный бинарный файл
в `.git/tools/gitleaks`. Git hooks не включаются автоматически при клонировании.

CI проверяет всю доступную историю с помощью Gitleaks и скрывает найденные
значения в логах. Это job `gitleaks` в `.github/workflows/ci.yml`: его ошибка
делает CI неуспешным и блокирует запуск CD по успешному завершению CI.
Проверка на GitHub происходит после отправки кода, поэтому локальный hook
нужно включать отдельно. Для ручного запуска:

```bash
gitleaks git . --log-opts="--all" --redact=100
```

Если Gitleaks установлен только в текущий клон, используйте
`.git/tools/gitleaks` вместо `gitleaks` в ручной команде.

Единственное исключение в `.gitleaksignore` — конкретное историческое
срабатывание на токен значка из стандартного README NestJS. Не добавляйте
реальные секреты в исключения.

Проверка не гарантирует обнаружения любого пароля. `.gitignore` не защищает
ранее отслеживаемые файлы и не удаляет данные из истории. Если реальный секрет
попал в GitHub, сначала отзовите или замените его, затем отдельно согласуйте
очистку истории и опубликованных артефактов.

## Результат проверки 30 октября 2026

Репозиторий GitHub был публичным. Проверены отслеживаемые файлы, 71 коммит
доступной на тот момент истории, опубликованные refs и pull request.
Боевых секретов в проверенном содержимом не обнаружено. Единственное
срабатывание Gitleaks совпало с токеном значка в upstream-шаблоне NestJS;
исключение ограничено конкретным коммитом, файлом, правилом и строкой.

Значения локальных `DATABASE_URL` и `JWT_SECRET` совпадали с опубликованными
development-значениями. Они не являются подходящими production-секретами.

Сверка с `.env.vps` не выполнена: SSH-доступ в сессии проверки отсутствовал.
GitHub API не предоставил доступ к логам Actions; содержимое артефактов также
не проверялось. Этот результат относится к перечисленным исходникам и истории,
а не ко всем данным сервера и GitHub.

После проверки добавлены общие Git-исключения и сканирование в CI, включён
локальный pre-commit hook. Проверка на искусственном секрете подтвердила,
что hook отклоняет такой staged diff. В новых клонах hook нужно включить заново.

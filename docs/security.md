# Проверка секретов

Файлы `.env` и `.env.*` во всех каталогах, стандартные имена файлов ключей
и резервные копии исключены через `.gitignore`. Файлы `*.example` содержат
только примеры. Не используйте значения из примеров и тестов в production.
Не передавайте секреты через `NEXT_PUBLIC_*` или Docker build arguments.

Для проверки перед каждым локальным коммитом установите Gitleaks 8.30.1
из официального проекта `gitleaks/gitleaks` (на macOS: `brew install gitleaks`)
и включите hook в своём клоне:

```bash
git config core.hooksPath .githooks
```

Hook проверяет staged diff и блокирует коммит при обнаружении секрета
или отсутствии сканера. Также поддерживается локальный бинарный файл
в `.git/tools/gitleaks`. Git hooks не включаются автоматически при клонировании.

CI проверяет всю доступную историю с помощью Gitleaks и скрывает найденные
значения в логах. Для ручного запуска:

```bash
gitleaks git . --log-opts="--all" --redact=100
```

Единственное исключение в `.gitleaksignore` — конкретное историческое
срабатывание на токен значка из стандартного README NestJS. Не добавляйте
реальные секреты в исключения.

Проверка не гарантирует обнаружения любого пароля. `.gitignore` не защищает
ранее отслеживаемые файлы и не удаляет данные из истории. Если реальный секрет
попал в GitHub, сначала отзовите или замените его, затем отдельно согласуйте
очистку истории и опубликованных артефактов.
